PowerShell 5.1+ & CMD

Lindows

Lightweight Linux commands for Windows — built so AI coding agents and developers never trip over missing Unix utilities again.

Want to try Lindows? Open PowerShell and run this one-liner to install Lindows, GNU Coreutils and ripgrep in one go:
irm https://raw.githubusercontent.com/lochgeo/lindows/main/install.ps1 | iex

That's it!

Why Lindows? (And Why Microsoft.Coreutils Alone Isn't Enough)

When running AI coding agents on Windows (Claude Code, OpenCode, Cursor, Codex, etc.), almost all of them naturally assume they are operating in a Linux or macOS environment.

Even if you install Microsoft.Coreutils via winget, coding agents still fail constantly on Windows because of three major gaps:

1. PowerShell Alias Collisions: PowerShell aliases take precedence over PATH executables. Even with Microsoft.Coreutils installed, when an agent runs rm -rf dist, mkdir -p a/b/c, or cat -n file.txt, PowerShell intercepts the command with its own built-in aliases (Remove-Item, mkdir, Get-Content) and crashes on the Unix flags! Lindows overrides those colliding aliases so Unix flags work.

2. System32\find.exe & tree.com Shadowing: Windows places legacy DOS find.exe and tree.com at the top of the system PATH. When an agent runs find . -name "*.ts" or tree -L 2 -I node_modules, Windows invokes the legacy binaries and fails. Lindows intercepts both so Unix expressions work natively.

3. Missing Non-Coreutils Tools: Microsoft.Coreutils does not ship grep, which, lsof (for lsof -i :3000 port checks), pkill / killall (for stopping background dev servers), tree, or man. Lindows provides all of them out of the box.

Pairing with Microsoft.Coreutils & ripgrep

By default, install.ps1 also ensures Microsoft.Coreutils and ripgrep are installed via winget so your Windows machine has the complete GNU/Linux toolset: 

winget install Microsoft.Coreutils
winget install BurntSushi.ripgrep.MSVC

If you only want the Lindows PowerShell/CMD shims without running winget, pass -SkipExtras to .\install.ps1.
